# 실행 로드맵과 진행 기준

기준일 2026-10-22. 목표는 2027년 NeurIPS의 벤치마크·평가 트랙이다. **2027년 공식 CFP·마감은 아직 확인하지 못했으므로 아래 날짜는 내부 계획**이다. 채택을 보장하는 일정이나 요구 규모가 아니다.

## 1. 첫 2주: 데이터가 성립하는지부터 확인

| 기간 | 할 일 | 리뷰 가능한 산출물 |
|---|---|---|
| Day 1–2 | AgentHop·SciNet·ResearchQA·faithfulness/sufficiency 연구의 본문·부록·release schema 대조 | 정확한 중복 요소·미충족 측정 대상 표, 1쪽 기여 명세 |
| Day 3–4 | 두 ML 하위 분야에서 실제 질문·논문 후보 40–60개 확보, 권리·버전 확인 | 후보 목록, 출처·제외 사유, 원문 고정 자료 |
| Day 5–7 | 기본 질문 30개와 FULL/CUT/PLACEBO/SCOPE 구성 | **120개 환경**, 조건표·대안 충분 근거·독립 주석 초안 |
| Day 8–10 | 두 명 독립 검수, 잔존 근거와 조건 불일치 검사, 분할·길이 shortcut 점검 | 원시 일치율·alpha/kappa, 잔존 근거 오류·제외 통계 |
| Day 11–12 | 동일 패킷에서 세 계열 모델·always-abstain·질문만 baseline | 모델 입력/출력 원본, 지표 초안, 비용 로그 |
| Day 13–14 | 전문가 오류와 기존/신규 지표의 관계 검토, 범위와 예산 결정 | 파일럿 보고서와 진행/수정/전환 결정 |

이것은 후속 실행 계획이다. 이번 문서 브랜치에서 30개 실문항, 120개 근거 환경, 모델 결과를 만들었다는 뜻은 아니다.

파일럿 문항은 본 평가와 분리하고, 개발 과정에서 공개한 문항을 비공개 test처럼 다시 쓰지 않는다. 30개 기본 질문으로 본 연구의 통계적 유의성을 확정할 수 없다. 제작 가능성과 오차 원인을 찾는 단계다.

## 2. 파일럿에서 정할 진행·수정·전환 기준

아래 수치는 미리 논의할 **운영 기준 제안**이다. 합격·채택 기준이나 이미 관측된 값이 아니다.

| 항목 | 진행에 필요한 증거 | 실패 시 조치 |
|---|---|---|
| 연구 차별성 | 가까운 공개 연구에 없는 측정 요소와 그 필요성을 설명 | 이름을 바꾸지 말고 기여 재설계 또는 체계적 감사로 전환 |
| 데이터 권리 | 핵심 공개 코퍼스에 제3자 재현이 가능한 권리·접근 경로 확보 | 공개 가능한 원천으로 좁힘 |
| 정답 재현성 | 원시 일치율 공개, verdict alpha/kappa 목표 0.75 이상, span/조건 별도 검사 | 분류 기준·질문 범위 재설계 후 재주석 |
| CUT 타당성 | 잔존 충분 근거 오류가 검수 사례의 5% 이하가 되도록 수정 | 대체 근거 탐색 강화, 불명확 사례 제외 |
| 실제 질문성 | 연구자 검수에서 사례의 가치와 조건 구분 필요성이 확인 | 단순 템플릿·꼬리잡기 질문 축소 |
| 추가 진단 가치 | 전문가가 확인한 중요한 오류가 정적 점수에 가려지는 사례 확보 | 기존 지표와의 중복을 인정하고 과제·분석 재검토 |
| Shortcut | 길이·문서 수·metadata만으로 환경의 정답을 쉽게 예측하지 못함 | 환경 매칭·주석·입력 계약 수정 |
| 비용·범위 | 그룹당 작업 시간의 실측치로 본 규모를 감당 가능 | 질문 수를 줄이고 독립 검수는 유지 |

상위 모델의 점수를 일부러 낮추기 위해 모호한 문항을 추가하지 않는다. 합의가 명확하고 실제로 중요한 오류를 측정하는지가 우선이다. 모델이 잘 푸는 결과나 그래프가 효과 없는 결과도 보고 대상이다.

## 4. 최소 인력과 비용을 계산하는 법

필요한 역할은 연구·평가 책임자 1명, 해당 하위 분야를 검수할 수 있는 주석자 최소 2명, 데이터·하네스 담당, 독립적인 불일치 조정자다. 역할은 겸임할 수 있지만 자기 작성 문항의 단독 최종 승인으로 대체하지 않는다. 기존 README의 팀원을 새 연구 인력으로 자동 배정하지 않는다.

### 전문가 시간

600개 기본 질문의 작업 시간을 다음처럼 가정하면:

- 후보 탐색·질문·gold 작성: 그룹당 45분 → **450시간**.
- 환경별 독립 검수: 600 × 4환경 × 2명 × 6분 → **480시간**.
- 불일치 조정·출처 재검사: 위 합계의 20% → **186시간**.
- 합계: **약 1,116시간**. 6분 검수 가정은 낙관적일 수 있으므로 파일럿 실측으로 교체한다.

보수를 시간당 25–50 USD로 **가정**하면 27,900–55,800 USD에 해당한다. 이는 시장 견적이 아니며, 팀 내부 인력의 기회비용도 포함해 계산한 시나리오다. 엔지니어링·논문 작성·외부 출력 채점·호스팅·세금·API 비용은 별도다. 파일럿 30개는 같은 가정에서 약 56시간이고, 초기 교육·프로토콜 설계 시간이 추가된다.

예산이 작다면 기본 질문 180개 × 4환경의 품질 높은 공개 핵심 집합부터 검토한다. 위 산식의 주석 시간은 약 335시간이다. 이 축소안도 논문 수준의 통계·대표성이 충분하다는 보장은 없으며, 본 실험의 군집 수와 검정력으로 판단한다.

### 추론 비용

API 가격을 고정해서 쓰지 않고 **실행 시점의 실제 단가**를 입력한다. 패킷 설정에서 6개 모델 × 2,400환경 × 1회, 환경당 입력 12,000 / 출력 1,500 tokens라면 입력 **172.8M**, 출력 **21.6M** tokens다.

```text
비용(USD) = 172.8 × 입력 1M-token 단가
           + 21.6 × 출력 1M-token 단가
```

모델마다 입력 길이·가격이 다르면 모델별로 계산해 합산한다. 캐시·추론 token·재시도·judge·임베딩·검색 agent의 여러 호출은 따로 더한다. 3회 반복은 해당 실행량을 3배로 만든다. 모든 조합을 처음부터 전수 실행하지 않고, 개발 집합에서 조건을 고정한 다음 본 비교와 대표 반복 실험에 배분한다.

30개 기본 질문 × 4환경 × 3모델의 파일럿은 360회이며 같은 token 가정에서 입력 4.32M / 출력 0.54M이다. 먼저 이 작업의 실제 로그로 분량·시간·비용을 추정한다. 이번 검토에서는 유료 모델 평가를 실행하지 않았다.

## 5. 후속 구현 순서

1. **TaskInput / GoldRecord 분리:** 질문·접근 가능한 코퍼스만 시스템에 전달하고 gold·환경 이름·필수 근거 표시를 숨긴다.
2. **원문 archive와 span 계약:** arXiv 버전·공개일·원문·변환 해시·권리·원문/정규화 좌표를 고정한다.
3. **대안 충분 근거와 조건 주석:** gold 관계를 live 서비스 그래프와 분리한다.
4. **근거 환경과 검증기:** 모든 검색·읽기·요약·캐시 경로에 같은 접근 제한을 적용한다.
5. **동일 패킷 evaluator:** 실패 포함 지표·주장별 인용·human rubric을 먼저 검증한다.
6. **고정 코퍼스 검색 비교:** 강한 BM25/dense/reranker에 동일 생성기·예산을 붙인 뒤 citation expansion을 추가한다.
7. **묶음 집계와 통계:** 환경·기본 질문·계보 군집을 분리하고 uncertainty와 결측을 보고한다.
8. **외부 재실행:** 구축에 참여하지 않은 사람이 샘플부터 돌려 데이터 접근과 해석을 검증한다.

새 CLI 이름·경로는 구현 단계에서 확정한다. 제안에 존재하는 명령을 이미 동작하는 것처럼 README에 쓰지 않는다.

## 6. 제출할 때 필요한 연구 산출물

- 주 기여인 공개 질문·근거 환경·조건·주장별 주석·rubric과 데이터 카드.
- 원문별 권리와 처리 버전, 제외 기준·데이터 통계·대체 근거 감사 기록.
- 실행 가능한 코드·고정 환경·baseline 설정·원시 출력·실패와 비용 로그.
- 개발/평가/보유 집합의 경계, 누출 검사, 군집 기반 통계와 human/judge 검증.
- 익명 리뷰용 접근 경로와 장기 유지·버전 수정 정책.
- 해당 연도 요구에 맞춘 Croissant core 및 RAI 메타데이터와 대용량이면 작은 검토 샘플.

이는 2026년 공식 지침을 참고한 준비 목록이다. 2027년 규정 확인이 필요하다. 비공개 보유 집합은 추가 진단 수단이며, 공개되지 않는 데이터가 주 기여가 되면 안 된다. [공식 FAQ](https://neurips.cc/Conferences/2026/EvaluationsDatasetsFAQ), [hosting 지침](https://neurips.cc/Conferences/2026/EvaluationsDatasetsHosting).

공개 브랜치는 연구 이력을 남기는 용도다. 투고 시 익명 artifact를 만들 때는 Git 이력·저자 정보·host metadata까지 해당 연도 규칙에 맞춰 처리한다. 이번 push는 투고나 외부 연구자 연락을 수행하는 단계가 아니다.
