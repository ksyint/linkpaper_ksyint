# 핵심 과제 v2: 필요한 문헌 수를 알려주지 않는 학술 근거 연결 QA

사용자 추가 요청 반영: **한 논문 또는 여러 논문에서 필요한 근거를 스스로 찾아 연결해 정답을 구한다. 참고해야 하는 논문 수는 알려주지 않는다.** 결과의 조건·원천을 추적해 재보고와 새 결과를 구별하는 과제는 전체의 한 하위 유형이다.

원천은 영어가 다수인 영어·한국어 논문이며 AI에 한정하지 않는다. 질문은 한국어 중심이고, 같은 원문에 대한 영어 대조 질문을 별도로 검수한다. 본 track은 텍스트·사람이 확인한 표 셀을 사용한다. 시각 인식은 별도 후속 track이다.

## 1. Agent에게 주는 것과 알려주지 않는 것

- 제공: 연구 질문, 공통 도구 설명·예산, 검색·열람·인용 탐색이 가능한 고정 문헌 archive.
- 비공개: 정답, 충분한 근거 조합, task 유형, 단일/다중 문헌 구분, 필요한 논문 수, 결과 그룹, evaluator split과 control arm.
- search/open으로 발견한 문헌의 제목·paper_id·버전·원문 위치는 정상적인 관측 정보다. 발견한 후보 수와 답에 필요한 논문 수는 다르다.

질문에는 '논문 두 편을 비교하라', '세 논문을 읽으면 된다' 같은 정답 문헌 수 힌트를 넣지 않는다. 방법·현상·대상·시점·평가 조건은 연구 질문에 필요한 만큼 명시할 수 있다. '두 방법'이라는 표현이 반드시 '두 논문'을 뜻하지도 않는다. 문항 파일명·ID·도구 schema·정렬 순서에 정답 유형이나 문헌 수를 암호처럼 넣지 않는다.

정답 문헌만 모아 작은 packet으로 제공하고 일반 검색 benchmark라고 부르지 않는다. 실제 core는 관련 후보와 방해 문헌이 있는 archive에서 시작하며, agent가 공개 도구로 발견한다. 현재 소형 합성 fixture는 이 계약을 검증하는 소프트웨어 예제다. 본 데이터의 규모·난도·노출 경계는 별도 감사한다.

## 2. 여섯 과제 유형

| 유형 / private task_type | 수행할 일 | 필요한 근거의 예 |
|---|---|---|
| 단일 논문 내 연결 / `within_paper_composition` | 한 논문 안의 떨어진 정보를 연결 | 방법의 모델 설정 + 표의 성능 + 본문의 자원 조건 |
| 논문 간 연결 / `cross_paper_bridge` | 정의·방법·결과를 매개로 관련 문헌을 찾아 연결 | 용어/방법을 정의한 문헌 + 적용·검증 결과를 보고한 문헌 |
| 조건을 맞춘 비교 / `condition_comparison` | 같은 지표·데이터·분할·예산인지 확인한 후 비교 | 실험 설정 + 결과표 + 비교 가능성의 제한 |
| 수치 추론 / `quantitative_reasoning` | 근거에서 피연산자·단위·분모를 찾아 계산 | 두 값 + 단위/측정 조건 + 계산식 |
| 상충·충분성 판단 / `conflict_and_sufficiency` | 조건 차이와 진짜 상충을 구분하고 부족한 근거를 인지 | 각 주장과 조건 + 조정 가능한 차이 + 남은 정보 부족 |
| 결과 원천 추적 / `result_provenance` | 재보고·새 결과·부분 재사용·확인 불가를 구분 | 원래 실험/분석 위치 + 후속 보고/인용의 연결 근거 |

유형은 겹칠 수 있다. 예를 들어 수치 추론이 조건 비교와 논문 간 연결을 함께 요구할 수 있다. 구현의 `Case.task_type`는 private primary 태그다. 추가 태그는 수집 장부에 기록하되, 이를 현재 schema가 모두 자동 처리한다고 표현하지 않는다. 숫자 6은 상호 배타적인 여섯 모집단을 증명하는 것이 아니다.

원천 추적이 아닌 과제에 결과 그룹 제출이나 GLRS를 강요하지 않는다. 한 논문에서 여러 근거를 연결하는 것도 core의 유효한 문제다. 논문이 많다는 이유만으로 더 어려운 문제라고 분류하지 않는다.

## 3. 정답·근거의 형태

정답 유형은 `short`, `numeric`, `explanation`, `decision`으로 구분한다. 단답·숫자·서술형을 모두 `supported`로 바꾸지 않는다. `decision`에서만 지지/반박/혼재/정보 부족을 판정한다. 서술형도 확인 불가 범위와 필요한 추가 자료를 설명할 수 있다.

수작업 정답에는 최종 답뿐 아니라 **주장 → 근거 → 연결/계산 단계**를 기록한다. 각 단계는 원문 위치·조건과 연결한다. 숫자는 원문 값, 분모, 단위, 계산식을 분리한다. 하나의 셀만 복사해 답할 수 있는 문항을 여러 단계 추론이라고 세지 않는다.

충분근거집합은 대안을 허용하는 OR-of-AND 구조다. 예를 들어 `{E1,E2}` 또는 `{E3,E4}`가 타당할 수 있고, 앞 조합은 한 논문·뒤 조합은 두 논문에 있을 수도 있다. 한 출제 경로나 특정 논문 수와 정확히 같아야 정답인 채점을 하지 않는다.

검수한 대안 근거 조합의 고유 paper 수들을 `known_alternative_paper_counts`, 근거 수를 `known_alternative_evidence_counts`로 private 집계한다. `global_minimum_certified=false`다. 이는 **알려진 충분근거집합의 paper 수**이며 코퍼스 전체의 절대 최소 논문 수 증명이 아니다. 새 유효 대안이 발견되면 사람 검수 후 registry·버전을 갱신하고 영향받은 평가를 재채점한다. 독립 검수 없이 '반드시 3편 필요'처럼 확정하지 않는다.

## 4. 전체 suite와 하위 지표의 역할

전체 suite는 답의 의미 정확성, 조건 일치, 충분한 근거 획득·연결, 인용의 지지 여부, 실패·유보·비용을 함께 보고한다. `structural_pass`나 문자열 reference 일치는 과학적 정답·증거 타당성의 인증이 아니다. 본 성능은 실제 reviewed 자료와 응답에 연결한 사람 평가로 확인한다.

정확한 `conditions` key·표기 일치는 strict 진단으로 유지하지만 의미 점수의 필수 gate로 쓰지 않는다. 의미 검수자는 실제 답변·주장 안의 조건 의미를 판정한다. trace·열람 인용·등록된 충분근거·판정형 계약은 별도로 검증하며 실패/누락/근거 불충분은 0점으로 남긴다. 유효한 응답의 의미 검수가 하나라도 대기 중이면 전체 과학적 의미 점수는 null이다. 검수된 subset만 평균내지 않는다.

새 유효 대안을 발견하면 어느 모델이 제시했는지 가리고 원문으로 독립 검토한다. 채택하면 gold·버전을 갱신하고 영향을 받는 모든 모델을 재채점하며 원래 결과·변경 사유도 보존한다. 특정 모델에 유리한 대안만 조용히 추가하지 않는다.

| 범위 | 보고할 항목 | 주의 |
|---|---|---|
| 전체 suite | 답변 의미·조건·근거 충분성·인용·오류율·검색/LLM 비용 | 답변 유형·task·source family별 적용 분모와 coverage |
| 단일/다중 근거 진단 | 같은 paper의 여러 근거 누락, 논문 간 bridge 누락, 대안 근거 활용 | private known support 수를 전역 최소로 해석하지 않음 |
| 비교·수치 | 조건 누락, 단위/분모 오류, 계산과 피연산자 검증 | 정규화·허용오차를 사전 동결. 문자열 일치만으로 계산 의미를 검증하지 않음 |
| 상충·충분성 | 정답 가능한 문제의 불필요한 유보, 부족한 문제의 과도한 확신 | 코퍼스 한정 부족과 학계 전체 부재 구분 |
| 결과 원천 하위 track | grouping·실제 열람/인용·matched B/R/N의 GLRS | 일반 QA에 GLRS=0을 부여하거나 전체 주 지표로 평균내지 않음 |

탐색 중단도 관측한다. 충분한 근거를 찾기 전 조기 종료, 확보 후 불필요한 검색, 예산 소진·중복 열람을 trace로 기록한다. 다만 정답 파일의 근거 수에 도달했다는 사실만으로 실제 의미상 충분성을 자동 확정하지 않는다. 후보 문헌이 더 존재한다는 이유만으로 계속 탐색해야 한다고 강요하지도 않는다.

## 5. 신규성·통계·현 상태

실험 환경은 **저장 archive**, **episode 도중 외부 논문 검색·fetch·로컬 색인·열람을 반복하는 live**, **실제 검색·원문 기록을 고정한 replay**로 구분한다. 별도 acquire-then-answer CLI는 수집/색인 단계를 분리하는 대조군이다. live와 사전 수집을 같은 실행으로 표현하지 않는다. 세부 범위·명령·coverage는 [획득 모드](ACQUISITION_TRACKS_KO.md)를 따른다.

학술 multi-hop·cross-paper QA 자체는 이미 연구된다. [PaperArena](https://arxiv.org/abs/2510.10909)는 여러 논문의 정보를 통합하는 도구 agent QA, [AgentHop](https://arxiv.org/abs/2609.34428)는 과학 QA의 retrieval/synthesis/tool/resource 진단, [ScholarGym](https://arxiv.org/abs/2601.21654)는 학술 정보 수집 단계 분해를 다룬다. 필요한 문헌 수를 알려주지 않는다는 설정만으로 세계 최초를 주장하지 않는다.

새 suite의 기여 후보는 실제 영어·한국어 다분야 문헌에서 **답·조건·근거 연결·충분성·원천**의 오류를 구분하고, 단일 논문과 다중 논문에서 발생하는 병목을 공정한 정보·예산으로 분석하는 것이다. 결과 계보 B/R/N은 그중 구체적인 진단 실험이다. 기존 benchmark/단순 baseline이 놓치는 새로운 발견은 실제 수작업 gold와 모델 실험으로 입증해야 한다.

5인×8개=40개 pilot 계획은 유지하되 모든 사람이 여러 유형의 후보를 찾는다. 특정 저자와 특정 task가 완전히 일치하게 배분하지 않는다. 번역·반복·하위 태그·B/R/N arm을 독립 문항 수에 더하지 않는다. 전체 평균과 task별 분포·유효 family 수·실패·권리/미확인 제외율을 함께 보고한다.

현재 실제 논문 3편의 교육용 CSV는 단일 논문 내 연결·비교·수치·계보 작성법을 보여 준다. 서로 무관한 세 논문을 묶어 교차 논문 실험을 완료했다고 하지 않는다. code의 새 `scholarly_qa` fixture는 가상 문헌이며 실제 benchmark 성능이 아니다.
