# 메인 논문에서 주장할 것과 그에 필요한 증거

목표는 주요 학회 main track이다. 기능 수·task 수·코드 분량을 채택 가능성의 증거로 쓰지 않는다. 현재는 독립 작성한 설계·프로토타입이며, 실제 수작업 gold·본 모델 비교·사람 기반 지표 타당성은 후속 검증 대상이다.

## 1. 현재 연구 질문

**필요한 문헌 수를 알려주지 않을 때, agent는 저장된 문헌과 외부에서 새로 확보해야 하는 문헌의 근거를 충분히 찾아 연결하고, 조건에 맞는 답을 낸 뒤 탐색을 끝낼 수 있는가?**

일반 학술 QA·외부 검색·도구 orchestration·한국어 지원은 선행연구가 있다. [PaperArena](https://arxiv.org/abs/2510.10909), [AgentHop](https://arxiv.org/abs/2609.34428), [ScholarGym](https://arxiv.org/abs/2601.21654), [K-BrowseComp](https://arxiv.org/abs/2606.02404)의 범위를 먼저 인정한다. '검색 도구를 붙였다' 또는 '논문 수를 안 알려준다'만으로 새 기여라고 하지 않는다.

## 2. 반증 가능한 주장 후보

| 주장 후보 | 필요한 실험·주석 | 주장을 낮춰야 하는 결과 |
|---|---|---|
| 답의 정확도만으로 발견·확보·연결·종료 실패를 설명하기 어렵다 | 실제 원문과 연결 단계, 허용 대안 근거, tool trace, 고정된 실패 taxonomy의 독립 검수 | 기존 정답/검색 점수만으로 같은 현상을 충분히 설명 |
| 저장 archive 성능과 live 논문 확보 성능에는 다른 병목이 있다 | 같은 질문의 offline/live/replay, 네트워크·fetch·parse와 답변 실패 분리, 실제 확보 내용·버전 대조 | 정보량·예산·provider 차이를 맞추면 추가 현상이 없음 |
| 단일/다중 문헌에서 근거 연결 방식·중단 오류가 다르다 | 필요한 문헌 수 비공개, 알려진 대안 충분집합·paper 수·단계 수의 private strata, source family 통제 | 문헌 수를 길이/난도의 대리 변수로 본 것만으로 설명되거나 대안 라벨 불안정 |
| 같은 결과의 재보고를 새 결과로 세는 오류가 존재한다 | 결과 원천 하위 track의 실제 교차 논문 계보·표현 유사도 교차·matched B/R/N | DOI/text dedup/common-parent 규칙으로 대부분 해결 |
| GLRS가 원천 하위 track에서 기존 지표를 보완한다 | 전문가 블라인드 출력 평가, 단순 정확도/F1/count 대비 추가 식별력·동점/0점률 | 사람 평가를 추가로 설명하지 못하거나 타당한 대안을 과도하게 감점 |

위 방향·크기는 측정 전 가설이다. 유리한 subset이나 모델 실패 사례만 골라 일반화하지 않는다. 다른 범위의 benchmark 점수를 하나의 우승 표로 합치지 않는다.

## 3. 필수 실험 묶음

1. **데이터 신뢰도:** 40개 pilot에서 원문 확보율·단가·조정 전 일치·대안 근거·미확인 비율을 먼저 잰다. 단위·단계 경계가 불안정하면 corpus 확대 전에 범위를 수정한다.
2. **공통 core:** 같은 생성기와 총 예산에서 단발 RAG, 반복 검색·열람, graph, planner/verifier를 비교한다. 원천 추적 모듈은 해당 하위 과제에서 따로 ablate한다.
3. **접근 환경:** 저장된 snapshot, 실제 episode 내 외부 발견·수집, 기록된 도구/본문 replay를 구분한다. 수집만 분리한 acquire-then-answer와 충분 근거 oracle-read를 진단 대조로 둔다.
4. **실패 분모:** 검색/다운로드/파싱/모델 오류와 확보 실패를 원래 예정 문항의 분모에 남긴다. 못 가져온 문제를 지우거나 원래 답을 정보 부족으로 바꾸지 않는다. 새 대안 근거는 사람 검수·버전 갱신 후 반영한다.
5. **비용·일반화:** 획득+QA 합산 tool/token/시간/비용, cold/warm 상태와 사전 색인 비용을 보고한다. 여러 모델 계열·새 source family·같은 원문 KO/EN 질문에서 확인하고 family 단위 불확실성을 계산한다.

## 4. 독립 작성·출처·오염 관리

- 원문 사실과 실제 연구자의 정보 요구에서 질문을 새로 작성한다. 다른 benchmark의 문제·정답·seed·prompt를 번역하거나 일부 바꾸어 자체 데이터로 공개하지 않는다.
- K-BrowseComp·KoTAU·다른 논문은 비교·설계 검토의 출처로 인용한다. 그들의 raw 데이터나 평가 규칙을 복제해 새 이름을 붙이지 않는다.
- 새 QA core·획득/live 모듈은 이 branch에서 작성한 구현이다. 원래 LinkPaper를 수정·재사용한 부분은 기존 MIT 고지·기여 기록과 Git 이력을 유지한다. third-party API와 라이브러리는 공식 문서·라이선스·버전을 기록한다.
- 문항 초안의 원문 hash·작성일·작성 주체·수정·검수 기록을 남긴다. source-family/버전/번역/통제 arm을 같은 split에 두고, 공개 예시·calibration은 숨겨진 test에서 제외한다.
- 질문 중복·가까운 paraphrase를 자동 후보 탐색 후 사람이 감사한다. 근거 문헌에 기존 benchmark 답안·평가 rubric이 섞이지 않았는지도 본다. 이것은 전 세계 표절 부재를 자동 인증하는 도구가 아니다.
- 유명 고전 논문 3편의 현재 CSV는 공개 작성법 예시다. 모델의 사전 노출 가능성이 높으므로 본 test의 오염 부재 증거로 쓰지 않는다. 본 test는 별도 source/time/family holdout을 구축하고 실제 모델 snapshot의 알려진 한계를 공개한다.

## 5. 논문에서 분리해 보고할 상태

합성 fixture 테스트, 실제 HTTP/PDF 연결 확인, scripted tool loop, 실제 LLM의 추론 성공, 사람 gold에 대한 과학적 성능은 서로 다른 증거다. 이전 tiny-model 형식 실패나 새 scripted online smoke를 본 benchmark 성능으로 바꾸어 쓰지 않는다. 코드·원문·실행 hash와 수행하지 않은 검증을 함께 기록한다.
