# 사람이 실제로 하는 라벨링

핵심 과제 v2에서는 한 문항마다 **① 원문 근거의 위치·조건·값, ② 근거를 연결하는 추론·계산 단계, ③ 질문의 정답과 허용 근거**를 CSV로 기록한다. 결과 원천 관계는 해당 하위 과제에서 주석한다. [논문별 3문항씩 총 9개 모범 예시와 빈 CSV](../../../collection_examples/20261102/csv_labeling/README_KO.md)는 숫자·단답·설명·판정형을 포함한다. 자동 추출 값이나 LLM 초안은 사람이 원문과 대조해야 한다.

## 1. 시작할 때 받는 자료

문항 작성자는 원문 PDF와 버전/출처 목록, 한국어 질문, 확인할 조건과 근거 연결 규칙을 준비한다. **한 논문 안의 여러 위치만으로도, 관련 여러 논문을 연결해서도 답할 수 있다.** 질문에 필요한 논문 수를 미리 쓰지 않는다. 원문 목록과 충분근거집합은 수집·검수용이며 agent에게 정답 문헌 목록으로 주는 입력이 아니다. PDF 안의 쪽수와 인쇄 쪽수를 구분한다.

현재 공유한 서로 다른 분야의 **3편은 수집 방법을 보여 주는 예시**다. 세 논문을 서로 같은 결과인지 비교하는 한 문항으로 묶는 것이 아니다. 실제 계보 문항에는 관련 문헌을 더 수집해야 한다. 아래 같은 PDF 안의 반복 보고는 라벨링을 배우는 연습 예시다.

먼저 공통 연습 1개로 기준을 맞춘다. 연습·토론에 쓴 자료는 조정 전 일치도(IAA)나 숨겨진 test에서 제외한다. 이후 실제 문항의 R1/R2는 PDF·질문·공통 규칙·**빈 양식**만 받고 각각 작성한다. 출제자의 잠정 정답·그룹·관계표와 상대 검수자의 답은 보지 않는다.

## 2. 세 CSV에 적는 내용

| CSV | 사람이 할 일 | 작성 단위 |
|---|---|---|
| `evidence_blank.csv` | 원문을 열고 관련 수치/서술을 찾아 위치·대상·조건·지표·값을 적는다. 같은 결과의 반복 위치도 별도 근거 ID로 적는다. | 질문 관련 결과를 담은 근거 한 개당 한 행 |
| `relation_blank.csv` | 결과 원천 하위 유형에서 재보고/새 결과/부분 재사용/확인 불가를 기록한다. 일반 QA의 정의→측정→계산 연결은 단계·의존관계 칸에 기록한다. | 관계를 판정하는 근거 쌍당 한 행 |
| `answer_blank.csv` | 답변 유형·필수 조건·모범답변·추론 단계·충분한 근거·대안을 기록한다. 판정형일 때만 네 분류 라벨을 붙인다. | 문항당 한 행 |

`adjudication_blank.csv`는 독립 검수가 끝난 뒤 조정자만 쓰는 기록이다. 원문에서 못 찾은 정보는 `원문 미확인/미보고`와 이유를 적는다. 명시적으로 판단할 수 없는 경우의 `확인 불가`와 아직 작성하지 않은 빈칸을 구분한다. 본인이 이해하기 어려운 분야는 `분야 검토 필요`로 보류한다.

### 2.1 근거는 이렇게 적는다

한국어 예시 [민수영·고영중(2024) 공식 원문](https://tkips.kips.or.kr/digital-library/101425), 「트랜스포머 인코더를 활용한 음절 단위 경량화 형태소 분석기」를 사용한다. 공유 PDF 파일명은 `03_KO_POS_Tagger.pdf`다.

아래는 **원본 PDF의 표·본문을 확인해 작성한 교육용 초안**이다. 두 사람이 독립 검수한 gold가 아니며, 검수자 이름과 최종 라벨을 대신 채우지 않았다.

| 칸 | 근거 `E01`에 적을 예 |
|---|---|
| 문헌 | `min2024`, 수집한 publisher PDF 버전 |
| 위치 | PDF 5쪽 / 인쇄 557쪽, Table 3 |
| 행·열 | `n_layers=6`, `Syllable-level Acc.`, `emb_dim=256` |
| 대상·데이터 | 세종 코퍼스. 평가 6,702문장·296,207음절은 PDF 4쪽 §4.1에서 확인 |
| 방법·설정 | 트랜스포머 인코더, 6계층, 임베딩 256차원 |
| 지표·단위 | 음절 단위 정확도, % |
| 원문 값 | `97.06%` |
| 임시 결과 그룹 | `U1` 후보. 최종 확정 전이며 그룹 이름 자체는 정답이 아님 |
| 미확인 사항 | 이 위치만으로 seed/신뢰구간은 확인하지 못함. 원문 전체에 없다고 단정하지 않음 |

다음으로 PDF 5쪽 **§4.5의 6계층·256차원 모델에 대한 음절 정확도 97.06% 서술**을 `E02`로 적는다. 위치는 다르므로 근거 ID는 다르다. 두 위치가 같은 모델·지표·평가의 결과를 되풀이한다는 것을 문맥으로 확인하면 같은 결과 그룹으로 묶는 후보가 된다.

같은 표의 **어절 정확도 96.37%**는 다른 지표·처리 단계이므로 별도 근거로 기록하고 질문 관련성을 따로 판단한다. 이를 음절 정확도와 섞거나 숫자 두 개를 곧바로 독립 실험 두 개로 세지 않는다. PDF 4쪽 Table 2의 **10.82%는 KorBERT 대비 파라미터 수 비율**이다. 정확도나 '10.82% 감소'로 바꾸어 적지 않는다.

### 2.2 관계 라벨은 네 가지다

| CSV 라벨 / 내부 용어 | 언제 선택하는가 | 선택 근거가 되지 않는 것 |
|---|---|---|
| 동일 결과 재서술 / `same_result_restatement` | 원래 표·실험·결과를 특정해 재서술/재인용하고 조건·값·원천이 대응함 | 숫자만 같음, 인용 링크만 있음 |
| 새 결과 보고 / `new_reported_unit` | 새 실험·측정·분석 또는 새 조건의 결과가 원문에서 식별됨 | 논문·DOI·저자가 다름 |
| 일부 재사용·확장 / `partial_reuse_or_extension` | 기존 결과를 쓴 부분과 새 결과 부분을 각각 원문으로 구분 가능 | 어디까지 재사용했는지 불명확함 |
| 확인 불가 / `unresolved` | 공개 원문만으로 결과 원천의 관계를 정할 수 없음 | 미작성을 대신하는 기본값으로 사용 |

예시 관계 행은 `E01 → E02 / 동일 결과 재서술(잠정) / Table 3와 §4.5 / 동일 모델 조건·음절 정확도와 주변 설명의 대응`이다. 원천이 확인되지 않으면 `확인 불가`로 바꾸고 추가로 필요한 원 논문·부록·실험 기록을 적는다.

새 보고 단위는 **통계적 독립성의 인증이 아니다**. 같은 데이터로 새 분석을 했을 수 있다. 표의 셀 수, metric 수, 시드 반복 수, 논문 수를 실험 수로 자동 계산하지 않는다. 질문에 관련된 결과 단위의 경계를 먼저 고정하고 주석한다. 한 문단에 예전 결과와 새 결과가 섞였으면 위치별 근거로 나눈다. 현재 GLRS의 원자적 근거 하나에는 unit을 최대 하나만 연결한다.

### 2.3 정답은 답변 유형과 조건을 먼저 정한다

일반 QA는 `short/numeric/explanation/decision`을 사용한다. 설명형·수치형을 억지로 `지지`로 바꾸지 않는다. 설명형에는 반드시 포함할 사실·조건·근거 연결을, 수치형에는 원문 피연산자·분모·단위·계산식·허용오차를 적는다. `decision`에서만 아래 네 분류를 쓴다. 기존의 표/본문 반복 예시는 결과 원천 하위 유형의 연습으로 유지한다.

새 CSV에서는 공개 질문 파일에 불투명 ID·질문·언어만 둔다. task 태그·답변 유형·알려진 충분근거의 논문 수·정답·단계는 교육용/검수용 파일에 분리한다. 이 공개 모범 답안을 본 사람이 같은 사례를 독립 평가했다고 기록하지 않는다.

교육용 판정 질문 예: **'이 PDF의 Table 3와 §4.5는 6계층·256차원 모델의 음절 정확도 97.06%에 대한 서로 다른 결과 보고 단위 두 개를 제시하는가?'**

위 두 위치가 같은 결과의 반복임을 확인한 경우의 잠정 판정은 `반박`이고, 답변에는 같은 결과가 두 위치에 서술되었다는 이유와 두 locator를 기록한다. 이는 작성법 예시이며 최종 사람 gold가 아니다. 실제 문항은 질문에 답하기 충분한 근거 조합과 타당한 대안 조합도 검수한다. 출제자가 처음 찾은 경로 하나만 정답으로 강제하지 않는다.

| 판정 | 의미 |
|---|---|
| 지지 / `supported` | 지정 조건과 근거 범위 안에서 해당 명제가 지지됨 |
| 반박 / `refuted` | 지정 조건과 근거 범위 안에서 해당 명제를 반박할 근거가 있음 |
| 혼재 / `mixed` | 조건을 맞춰도 지지·반박 결과가 함께 있으며 그 범위를 구체적으로 설명할 수 있음 |
| 정보 부족 / `insufficient` | 고정된 원문 범위로 명제를 결정할 수 없음. 부족한 정보와 확인한 범위를 기록 |

`혼재`는 검수자끼리 의견이 다르다는 뜻이 아니다. `정보 부족`은 학계 전체에 근거가 없다는 뜻이 아니다.

## 3. 누구의 어떤 파일을 남기는가

김수용이 출제한 문항이라면 **정상헌 R1, 남두현 R2, 오창원 조정자**로 진행한다. 다른 출제자는 [순환 배치표](TEAM_AND_DATA_KO.md#31-출제자와-분리한-순환-review조정-표)를 따른다.

| 출제자 | R1 | R2 | 조정자 |
|---|---|---|---|
| 김수용 | 정상헌 | 남두현 | 오창원 |
| 정상헌 | 남두현 | 오창원 | 이상민 |
| 남두현 | 오창원 | 이상민 | 김수용 |
| 오창원 | 이상민 | 김수용 | 정상헌 |
| 이상민 | 김수용 | 정상헌 | 남두현 |

1. 수집자는 원문·질문 packet과 자신의 잠정 주석을 따로 보관한다. 잠정 정답 파일은 R1/R2에게 보내지 않는다.
2. R1은 `case001_R1/`, R2는 `case001_R2/` 폴더에 빈 CSV 3개를 각각 복사해 작성한다. 실제 본인이 원문을 확인한 뒤 자신의 이름을 적는다. 같은 파일을 돌려 보며 합의한 뒤 두 번 서명하는 방식은 독립 검수가 아니다.
3. 두 파일 제출 후 원본을 잠그고 **조정 전** 일치도와 불일치를 집계한다. R1의 U1과 R2의 U3라는 문자열 차이 대신 어떤 근거를 같은 그룹으로 묶었는지를 비교한다.
4. 출제자·R1·R2와 다른 조정자가 불일치를 원문으로 확인해 `adjudication_blank.csv`의 사본과 별도 최종본을 작성한다. 최초 두 판정을 덮어쓰지 않는다. 해결되지 않으면 확인 불가를 유지한다.
5. 최종 코드 변환에서 근거 ID·결과 그룹·질문 판정·대체 근거를 연결한다. CSV는 사람 입력 양식이고 evaluator JSON으로 자동 변환하는 기능은 이번 양식에 포함하지 않았다.

결과 계보가 미확인인 unit은 null로 둔다. 해당 eligible 근거가 포함된 triplet은 확정 GLRS에서 제외하고 제외율을 보고하며, 정보 부족을 알아보는 과제로는 별도 유지할 수 있다. agent의 오류/실패를 이 제외 사유로 바꾸지 않는다.

## 4. 한 문항의 완료 기준

- 관련 원문·버전·근거 위치·조건·지표·값이 확인되었다.
- 질문의 판정 대상, 결과 단위 경계, 같은 결과/새 결과/확인 불가의 근거가 적혀 있다.
- 질문 정답과 충분 근거·허용 대안, 미확인 사항이 기록되어 있다.
- 작성자와 다른 두 검수자의 원본 및 별도 조정 기록이 있다.
- 사람 판정·권리·누출 검토가 끝나기 전에는 `reviewed/frozen`으로 바꾸지 않았다.

처음에는 이 절차로 **연습 한 문항을 끝내 보는 것**부터 시작한다. 각자 8개라는 계획은 PDF 8개 다운로드가 아니라 이 절차를 통과한 기본 문항 8개를 뜻한다.
