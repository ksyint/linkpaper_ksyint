# CSV 라벨링 예시: 필요한 논문 수를 알려 주지 않는 근거 연결 QA

핵심 과제는 **하나 또는 여러 논문에서 필요한 근거를 찾아 연결하고 정답을 내는 것**이다. 질문에 몇 편을 참고해야 하는지 알려 주지 않는다. 결과 원천·재보고 구별은 여러 task 중 하나다. 원천은 영어 다수·한국어 포함이고 주제는 AI에 한정하지 않는다.

**공유용 논문 3편 × 모범 문항 3개 = 총 9개**를 유지했다. 이번 실제 원문 예시는 한 논문 안의 방법·설정·표·본문을 연결하는 작성 연습이다. 서로 무관한 이 세 논문을 교차 논문 근거인 것처럼 묶지 않았다. 실제 교차 논문 task에는 관련 원 논문·후속·인용 문헌을 별도로 확보해야 한다.

원문 대조로 채운 교육용 초안이며 `교육용_독립검수전`, `최종gold여부=false`, 실제 검수자 빈칸으로 둔다. 사람 2인의 독립 검수를 마친 연구용 gold나 본 평가 성능이 아니다. 본 코드로의 자동 CSV→JSON 변환 기능도 포함하지 않았다.

## 질문 파일과 교사용 라벨을 구분한다

- **[public_questions.csv](public_questions.csv)**는 불투명한 문항 ID·질문·언어 세 필드만 담는다. 과제 유형·정답·근거 ID·필요 논문 수를 넣지 않았다. 연구 대상 식별을 위한 모델·저자 이름이나 조건은 질문에 자연스럽게 포함할 수 있다.
- **[answer_examples.csv](answer_examples.csv)**는 교사/평가자용이다. task 유형·답 유형·모범답변·근거 연결 단계·계산식·허용 대안·알려진 충분 조합의 논문 수를 담으며 agent 입력으로 주지 않는다. 공개 교육용 예시 전체를 읽고 학습한 모델의 수치를 숨겨진 test 성능으로 발표하지 않는다.
- **[evidence_examples.csv](evidence_examples.csv)**는 총 18행이다. 원문 위치·대상·조건·지표·값과 방법/설정/데이터/결과의 역할을 나눠 적었다. 방법이나 데이터 근거에 결과 unit ID를 억지로 붙이지 않는다.
- **[relation_examples.csv](relation_examples.csv)**는 결과 원천 task를 위한 보조 예시 3행이다. 일반 QA 전부에 계보 그룹 제출이나 GLRS를 강요하지 않는다.

CSV는 UTF-8 BOM·LF다. `;`는 확인 근거 나열, `+`는 한 충분 근거 조합, `|`는 대안 조합/허용 표현이다. `근거연결단계_비공개`에는 S1·S2 등 단계와 역할을, `단계의존관계_비공개`에는 어느 단계가 어떤 근거에 의존하는지 적는다. `계산피연산자·식_비공개`는 원문 값과 사람이 계산한 파생값을 구분한다.

## 논문마다 채운 3문항

| 논문 | 문항 | private 주요 task / 답 유형 | 모범 답의 핵심 |
|---|---|---|---|
| BatchNorm / `ioffe15` | BN-Q01 | quantitative_reasoning / numeric | 목표 정확도 72.2% 조건에서 Inception 3,100만→BN-Baseline 1,330만 step. 감소율 약 **57.10%** |
| BatchNorm | BN-Q02 | condition_comparison / explanation | 210만 step 보고와 학습률 0.0015→0.0075·추가 변경을 연결. BN 단독 효과로 분리할 수 없음 |
| BatchNorm | BN-Q03 | result_provenance / decision | Inception 3,100만 step의 그림/본문 보고는 같은 원 결과를 재서술한 후보. 별도 unit이라는 명제는 반박 |
| 생물다양성 / `mora2011` | MORA-Q01 | quantitative_reasoning / numeric | 지구 진핵생물 예측 8,740,000−등록 1,233,500 = **7,506,500종**. 실측 미발견 총수와 구분 |
| 생물다양성 | MORA-Q02 | within_paper_composition / explanation | 해양 등록 193,756·예측 2,210,000·SE 182,000과 방법 설명 연결. 예측/직접 집계 및 SE/95% CI 구분 |
| 생물다양성 | MORA-Q03 | conflict_and_sufficiency / explanation | 등록치와 불확실한 예측만으로 실제 전체 종수의 정확한 정수는 확정할 수 없다고 설명 |
| 한국어 형태소 분석 / `min2024` | KO-Q01 | within_paper_composition / explanation | 최고 음절 성능 설정 6계층·256차원, 평가 6,702문장·296,207음절, 음절 97.06%·어절 96.37% 연결 |
| 한국어 형태소 분석 | KO-Q02 | quantitative_reasoning / numeric | 같은 모델의 KorBERT 대비 파라미터 비율 10.82%에서 **89.18% 절감**을 계산. 정확도와 구분 |
| 한국어 형태소 분석 | KO-Q03 | within_paper_composition / short | 음절 태깅 뒤 사전 복원·추가 태깅을 거친 출력을 평가한 것은 **어절 단위 정확도** |

`57.10%`, `7,506,500종`, `89.18%`는 CSV에 적은 피연산자와 식으로 계산한 **파생값**이다. 원문이 그 감소율/차이를 직접 보고했다고 쓰지 않았다. 이 작은 예시는 여섯 유형 중 실제 근거가 있는 다섯 유형을 보여 주며, cross_paper_bridge 실데이터를 확보했다고 주장하지 않는다.

일반 QA의 답 유형은 `decision/short/numeric/explanation`이다. 숫자·단답·설명 답에 `supported`를 일괄 부여하지 않는다. `판정_해당시`는 판정형이거나 명시적인 정보 부족을 기록할 때만 사용한다. `혼재`는 검수자 간 의견 불일치가 아니라 동일 조건에서 지지·반박 근거가 공존할 때의 판정이다.

| [evidence_blank.csv](evidence_blank.csv) | 근거마다 위치·대상·조건·역할·결과 서술을 한 행에 기록 |
| [answer_blank.csv](answer_blank.csv) | 문항마다 공개 질문·private task·답 유형·정답·근거 연결 단계·계산·허용 대안을 기록 |

| [adjudication_blank.csv](adjudication_blank.csv) | 독립 제출 후 조정자가 불일치와 최종 사유를 기록 |

R1/R2는 각자 별도 폴더에 빈 CSV를 복사한다. 원문·질문·공통 규칙으로 독립 작성하고 출제자의 잠정 정답이나 상대 답은 보지 않는다. 작성자·R1·R2와 다른 조정자가 원문으로 불일치를 확인하고, 최초 CSV와 조정 기록을 모두 보존한다. 이 모범 예시에 쓰인 자료는 연습용이며 IAA나 숨겨진 test에서 제외한다.

## 필요한 논문 수는 정답에서 검증하되 agent에게 주지 않는다

충분 근거의 타당한 대안 조합은 여러 개일 수 있다. 한 조합이 한 논문에서 나오고 다른 조합이 여러 논문에서 나올 수도 있으므로 무조건 한 정답 경로·논문 수를 강제하지 않는다. `알려진충분조합별논문수_비공개`는 **현재 적은 유효 조합에 등장하는 고유 논문의 수**이며 전 세계 가능한 모든 해결 경로의 최소 논문 수를 증명한 값이 아니다. 이번 교육 자료는 알려진 조합 모두 한 논문 안에 있지만, 질문에는 그 수를 알리지 않고 `최소논문수확정여부_비공개=false`를 유지했다.

정보 부족 문항의 확인 근거는 읽어 본 범위이며 결정적인 정답의 충분 집합과 다르다. 해당 행의 `충분근거조합_비공개`와 조합별 논문 수는 비웠다. '정확한 실제 값은 미확정'과 '전 세계에 자료가 전혀 없다'를 혼동하지 않는다.

결과 원천 task의 unknown unit은 null로 두고, 해당 eligible 계보가 미확인인 triplet은 확정 GLRS에서 제외·제외율 보고 대상으로 둔다. 다른 QA task의 근거가 계보 ID를 갖지 않는다는 이유만으로 감점하지 않는다. GLRS는 전체 benchmark의 보편 정답 점수가 아니다.

## 오프라인과 외부 논문 탐색 모드

같은 유형의 질문을 사전 색인된 offline 원문에서 풀거나, 외부에서 관련 논문을 찾고 원문을 확보하는 live discovery/fetch 모드로 실행할 수 있다. live run은 실제 검색·접근 결과와 버전/수집 시점·실패를 기록하고 확보한 근거를 별도 snapshot으로 고정해야 한다. 이 폴더는 로컬에 수집한 원문을 사용한 라벨링 예시이며, 외부 탐색 agent의 성공이나 end-to-end live 평가를 실행했다는 증거가 아니다.
